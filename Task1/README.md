# Task 1. Анализ безопасности системы «Медикаменте»

## Состав решения

- **`problems.md`** — список проблемных зон текущих процессов работы с данными (As-Is), сопоставленный с требованиями безопасности и архитектурными практиками.
- **`data-classification-and-protection.md`** — список данных для защиты со способами защиты (шифрование / обфускация / обезличивание), механизм тегирования данных и перечень инструментов/мер по потокам.
- **`DFD-as-is.drawio`** (+ рендеры в `png/DFD-as-is-p1..5.png`) — диаграммы потоков данных по 5 бизнес-процессам:
  1. Регистрация и запись пациента
  2. Приём пациента и ведение медицинской карты
  3. Учёт анализов (лаборатория)
  4. Оплата медицинских услуг
  5. Учёт ТМЦ и снабжение
- **`DFD-protected.drawio`** (+ рендеры в `png/DFD-protected-p1..5.png`) — те же диаграммы, доработанные: на хранилищах и потоках указаны теги чувствительности (`PII-BASIC`, `PII-EXTENDED`, `PHI-SENSITIVE`, `FIN-PII`, `PII-HR`, `INTERNAL`) и требуемые меры защиты.

## Как читать диаграммы

- Синий прямоугольник — внешняя сущность (человек/отдел).
- Красный пунктирный прямоугольник — внешняя система без цифровой интеграции (Лаборатория).
- Зелёный скруглённый прямоугольник — процесс.
- Жёлтый/оранжевый прямоугольник — хранилище данных (файл, 1С, ККМ); в защищённой версии подписан тегом и мерой защиты.
